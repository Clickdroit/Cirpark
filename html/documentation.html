🏗️ Architecture générale

Vue d'ensemble

Cirpark est un système de gestion de parking intelligent composé de trois couches :


┌─────────────────────────────────────┐
│      INTERFACE WEB (Frontend)       │
│  - HTML/CSS/JavaScript              │
│  - Dashboard temps réel             │
│  - Statistiques & Historique        │
└──────────────┬──────────────────────┘
               │ HTTP/AJAX
┌──────────────▼──────────────────────┐
│      API REST (Backend PHP)         │
│  - rest.php                         │
│  - CRUD Capteurs/États/Config       │
│  - Gestion des requêtes             │
└──────────────┬──────────────────────┘
               │
      ┌────────┴────────┐
      │                 │
      ▼                 ▼
  ┌─────────────┐  ┌──────────────┐
  │  MySQL BDD  │  │ UDP Client   │
  │  Cirpark    │  │ Port 10001   │
  └─────────────┘  └──────┬───────┘
                          │ UDP
                   ┌──────▼──────┐
                   │  Capteurs   │
                   │  Ultrason   │
                   │  Modbus RTU │
                   └─────────────┘

Composants principaux

Composant Rôle Technologie
Frontend Interface utilisateur, affichage temps réel HTML5, CSS3, JavaScript, Chart.js
API REST CRUD des ressources, orchestration PHP 8, PDO
Base de Données Stockage des données persistantes MySQL/MariaDB
UDP Client Communication avec capteurs, polling PHP Sockets (cirpark_client_udp.php)

Flux de données

1. Acquisition données capteurs :

  • cirpark_client_udp.php s'exécute toutes les 60 secondes
  • Récupère liste des capteurs depuis la BDD
  • Envoie requête Modbus RTU via UDP au serveur capteurs
  • Reçoit réponse et stocke l'état dans la table 'etat'

2. Consultation données :

  • Frontend effectue requêtes AJAX vers l'API REST
  • API retourne les données au format JSON
  • Frontend met à jour l'interface en temps réel

POST - Création de données

1. Créer un capteur

POST /rest.php/capteur

Body (JSON) :

{
  "nom": "SP1726",
  "type": "Normale",
  "numero": "1726",
  "description": "Capteur Ultrason"
}

Réponse (201 Created) :

{"message": "Capteur ajouté"}

2. Ajouter un état

POST /rest.php/capteur/etat

Body (JSON) :

{
  "id_capteur": 1,
  "etat": "Occupee"
}

3. Ajouter une configuration

POST /rest.php/capteur/configuration

Body (JSON) :

{
  "id_capteur": 1,
  "hauteur": 150,
  "eclairage": 1
}

PUT - Modification de données

1. Modifier un capteur

PUT /rest.php/capteur/{id}

Body (JSON) :

{
  "nom": "SP1700_Updated",
  "type": "Reserve",
  "numero": "1700",
  "description": "Capteur Ultrason modifié"
}

2. Modifier un état

PUT /rest.php/capteur/etat/{id_capteur}

Body (JSON) :

{"etat": "Libre"}

3. Modifier une configuration

PUT /rest.php/capteur/configuration/{id_capteur}

Body (JSON) :

{
  "hauteur": 200,
  "eclairage": 0
}

DELETE - Suppression de données

1. Supprimer un capteur (et toutes ses dépendances)

DELETE /rest.php/capteur/{id}

Supprime également tous les états et configurations associés

2. Supprimer les états d'un capteur

DELETE /rest.php/capteur/etat/{id_capteur}

3. Supprimer la configuration d'un capteur

DELETE /rest.php/capteur/configuration/{id_capteur}

Codes de réponse HTTP

Code Signification
200 OK Requête réussie
201 Created Ressource créée avec succès
400 Bad Request Champs manquants ou invalides
500 Internal Server Error Erreur de connexion à la BDD ou serveur

📡 Protocole UDP - Communication avec les capteurs

Vue d'ensemble

Les capteurs communiquent via le protocole Modbus RTU sur UDP. Le script cirpark_client_udp.php effectue un polling régulier toutes les 60 secondes.

Configuration

Paramètre Valeur
Serveur 172.18.112.249
Port 10001
Protocole UDP/Modbus RTU
Intervalle 60 secondes

Format des trames Modbus RTU

Requête (Request) :

┌─────────┬─────────┬──────────┬─────┐
│ Addr H  │ Addr L  │ CodeFunc │ BCC │
│ 1 byte  │ 1 byte  │ 1 byte   │ 1b  │
└─────────┴─────────┴──────────┴─────┘

Exemple pour capteur 0x1700:
┌──────┬──────┬────────┬────┐
│ 0x17 │ 0x00 │ 0x10   │ 0x27│
└──────┴──────┴────────┴────┘

Réponse (Response) :

┌──────────┬──────────┬────────┬──────────┐
│ Addr H   │ Addr L   │ Etat   │ Data...  │
│ 1 byte   │ 1 byte   │ 1 byte │ N bytes  │
└──────────┴──────────┴────────┴──────────┘

États retournés:
0x00 = Libre (place disponible)
0x01 = Occupée (place occupée)
Autre = Erreur/Inconnu

Calcul du BCC (Block Check Code)

BCC = (Addr_H + Addr_L + Code_Fonction) mod 256

Exemple:
0x17 + 0x00 + 0x10 = 0x27
BCC = 0x27

Processus de communication

1. Boucle infinie toutes les 60s:
   ├─ Récupérer liste capteurs (SELECT id, numero FROM capteur)
   │
   ├─ Pour chaque capteur:
   │  ├─ Parser le numéro hexadécimal
   │  ├─ Calculer le BCC
   │  ├─ Créer trame Modbus RTU
   │  ├─ Envoyer via UDP
   │  ├─ Recevoir réponse
   │  ├─ Parser l'état (byte[2])
   │  ├─ Insérer dans table 'etat' avec timestamp NOW()
   │  └─ Afficher logs
   │
   └─ Attendre 60 secondes

Exemple logs:
"message envoyé : 17001027"
"La réponse est : 170000"
"La place est libre !"
"INSERT INTO etat (etat, date_heure, id_capteur)..."

Gestion des erreurs

  • BDD indisponible : Message "BDD : ECHEC" et arrêt
  • Timeout UDP : Socket timeout après attente réponse
  • État inconnu : Enregistrement en tant que "Inconnu"
  • Socket error : Logs affichés, boucle continue

Exécution du client UDP

php cirpark_client_udp.php

(À mettre en place comme service/daemon en production)

Exemple avec nohup (Linux):
nohup php /path/to/cirpark_client_udp.php > logs/udp_client.log 2>&1 &

Exemple avec Task Scheduler (Windows):
Action: php.exe
Paramètres: C:\path\to\cirpark_client_udp.php
Répéter: Continuellement

🗄️ Schéma Base de Données

Vue d'ensemble

La base de données cirpark contient 3 tables avec les relations suivantes :

┌──────────────┐
│   CAPTEUR    │
├──────────────┤
│ PK: id       │───────┐
│ nom          │       │ FK
│ description  │       │
│ numero       │       │
│ type         │       │
└──────────────┘       │
                       │
        ┌──────────────┴──────────────┐
        │                             │
        ▼                             ▼
┌──────────────┐            ┌──────────────┐
│    ETAT      │            │CONFIGURATION │
├──────────────┤            ├──────────────┤
│ PK: id       │            │ PK: id       │
│ FK: id_capteur           │ FK: id_capteur
│ etat         │            │ hauteur      │
│ date_heure   │            │ eclairage    │
└──────────────┘            └──────────────┘

Table CAPTEUR

Colonne Type Contraintes Description
id INT PK, AUTO_INCREMENT Identifiant unique
nom VARCHAR(20) Nullable Ex: SP1700
description VARCHAR(100) Nullable Ex: Capteur Ultrason
numero VARCHAR(11) Nullable Adresse Modbus (hex): 1700
type VARCHAR(20) Nullable Normale | Interdit | Reserve

Table ETAT

Colonne Type Contraintes Description
id INT PK, AUTO_INCREMENT Identifiant unique
id_capteur INT FK → capteur.id Référence au capteur
etat VARCHAR(20) Nullable Libre | Occupée | Inconnu
date_heure DATETIME Nullable Timestamp du relevé

Table CONFIGURATION

Colonne Type Contraintes Description
id INT PK, AUTO_INCREMENT Identifiant unique
id_capteur INT FK → capteur.id Référence au capteur
hauteur INT Nullable Hauteur capteur en cm
eclairage TINYINT Nullable Éclairage (0 ou 1)

Requêtes SQL utiles

Tous les capteurs avec leur dernier état :

SELECT c.*, e.etat, e.date_heure, conf.hauteur, conf.eclairage
FROM capteur c
LEFT JOIN etat e ON c.id = e.id_capteur
  AND e.id = (SELECT MAX(id) FROM etat WHERE id_capteur = c.id)
LEFT JOIN configuration conf ON c.id = conf.id_capteur;

Statistiques d'occupation :

SELECT 
  COUNT(*) as total_places,
  SUM(CASE WHEN e.etat = 'Occupée' THEN 1 ELSE 0 END) as occupees,
  SUM(CASE WHEN e.etat = 'Libre' THEN 1 ELSE 0 END) as libres
FROM capteur c
LEFT JOIN etat e ON c.id = e.id_capteur
  AND e.id = (SELECT MAX(id) FROM etat WHERE id_capteur = c.id);

Historique des états d'un capteur :

SELECT * FROM etat 
WHERE id_capteur = 1 
ORDER BY date_heure DESC 
LIMIT 100;

Places par type :

SELECT type, COUNT(*) as nombre
FROM capteur
GROUP BY type;
